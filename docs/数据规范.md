# 「红妆」诗词背诵软件 — 数据规范

- 文档版本：v1.1
- 建立日期：2026-11-02
- 状态：✅ 生效中（已按本规范录入 200 首 + 2612 字 + 1156 双字词；扩充目标 4200 首）
- 关联文档：《需求文档》附录 A/B、《技术方案》、《交接文档》§6.2 扩充流水线

本规范定义三份内置数据文件（`assets/data/`）的结构与录入规则，是诗词库与字库**后续持续扩充的唯一标准**。任何新增数据必须遵守本规范。

## 1. 文件清单

| 文件 | 内容 | 规模（首批） |
| --- | --- | --- |
| `poems.json` | 诗词条目（正文、翻译、注释、元数据） | 200 首（目标 4200） |
| `dict.json` | 字库 + 双字词（数据集内出现的全部字/词） | 2612 字 + 1156 词（以实际扫描为准） |
| `categories.json` | 体裁 → 主题两级分类与标签元数据 | 4 类 + 标签枚举 |

## 2. poems.json — 诗词条目

### 2.1 顶层结构

```json
{
  "dataVersion": "1.0.0",
  "items": [ { "一首诗的条目，见 2.2" } ]
}
```

### 2.2 条目结构

```json
{
  "id": "tang-001",
  "category": "唐诗",
  "tags": ["思乡"],
  "title": "静夜思",
  "subtitle": "",
  "author": "李白",
  "dynasty": "唐",
  "excerptOf": null,
  "excerptNote": "",
  "content": "床前明月光，疑是地上霜。\n举头望明月，低头思故乡。",
  "translation": "明亮的月光洒在床前，好像地上泛起了一层白霜。抬头望见天上明月，不由得低头思念起远方的故乡。",
  "notes": [
    { "term": "床", "meaning": "此处指井上围栏或坐卧之具，古义有争议；一说指井栏。" },
    { "term": "疑", "meaning": "好像，仿佛。" }
  ]
}
```

### 2.3 字段说明

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| `id` | string | 是 | 全库唯一、稳定不变。格式：体裁拼音缩写-3位序号，如 `tang-001`、`song-001`、`yuan-001`、`guwen-001`；扩充到 1000 首以上时序号升为 4 位（如 `tang-1000`） |
| `category` | string | 是 | 仅限：`唐诗` / `宋词` / `元曲` / `古文` |
| `tags` | string[] | 是 | 二级主题标签，取自附录 B 枚举；可多标签 |
| `title` | string | 是 | 展示标题（含词牌/曲牌/篇名） |
| `subtitle` | string | 否 | 副题（如"明月几时有""赤壁怀古"）。词牌在 title、首句主语在 subtitle |
| `author` | string | 是 | 作者名（多名作者用顿号分隔） |
| `dynasty` | string | 是 | 朝代（如：唐、宋、元、东晋、南朝·梁、五代·南唐） |
| `excerptOf` | string/null | 否 | 若为节选，填原篇全名；全文收录填 null |
| `excerptNote` | string | 是 | 节选范围说明或空字符串 |
| `content` | string | 是 | 正文。段落用 `\n` 分隔，句内用全角标点；每句不换行（长文每段一行） |
| `translation` | string | 是 | 全文现代化翻译，按段落用 `\n` 分隔，与 content 段落对应 |
| `notes` | object[] | 是 | 精简关键注释（见 2.4） |

### 2.4 notes 注释规则（精简注释）

- 每首 3~10 条关键注释，只注释影响理解的字词、典故、名物，不逐字注。
- 每条：`term`（被注字词）+ `meaning`（一句话释义）。
- 节选篇目仅注释所选节选部分。

### 2.5 录入规则

1. **文本**：采用通行版本，简体中文；异文差异取主流教材版本。
2. **标点**：全角中文标点；词/曲正文按阕或段落换行。
3. **多音字**：字库中收录各读法并注明在本篇中的正确读音（在 notes 或字库中体现）。
4. **准确性**：录入后逐首人工校对一遍正文（错一字即失真）。

## 3. dict.json — 字库

### 3.1 结构

```json
{
  "dataVersion": "1.0.0",
  "chars": {
    "床": {
      "pinyin": ["chuáng"],
      "meanings": ["供人睡卧的家具。"],
      "ancient": ["井上围栏；一说坐卧之具（常用于古诗中）。"]
    },
    "还": {
      "pinyin": ["huán", "hái"],
      "meanings": ["返回；归还。", "副词，仍旧。"],
      "ancient": ["通\u201c环\u201d，环绕。"],
      "wordMeanings": {
        "还家": "回家。"
      }
    }
  },
  "words": {
    "明月": "明亮的月亮。",
    "故乡": "家乡。"
  }
}
```

### 3.2 字段说明

| 字段 | 说明 |
| --- | --- |
| `chars` | 字 → 释义的映射。键为单个汉字 |
| `chars.拼音` | 该字全部读法的全拼数组，按常用度排序 |
| `chars.meanings` | 现代汉语常用义项（与拼音数组对应或合并） |
| `chars.ancient` | 古汉语常见义项（可选，有则列） |
| `chars.wordMeanings` | 该字作为词头时涉及的重点词组释义（可选） |
| `words` | 词 → 释义映射，覆盖正文中出现的重点双字词（长按成词查询优先命中） |

### 3.3 覆盖与录入规则

1. **覆盖范围**：扫描全部诗词正文的**全部字符**（含冷僻字），保证「长按必有结果」。
2. **释义深度**：古汉语常用义优先，每字 1~4 个义项，语言简短。
3. **多音字**：必须列全会出现的读音；每首诗内采用正确读音。
4. **生成方式**：用脚本扫描正文收集用字清单 → 人工按清单录入释义 → 校验清单 100% 覆盖。
5. **扩充时**：新增诗词后重新扫描，仅补录新出现字。

## 6. 数据扩充流程（标准动作）

小规模增补按以下 1~5 步；**大规模扩充（当前待办：200 → 4200 首）按《交接文档》§6.2 已验证的并行流水线执行**，其要点：

1. 在《需求文档》附录 A 表格中新增篇目并提交项目负责人审核。
2. 按第 2 节格式录入 poems.json，人工校对正文。
3. 扫描新增正文用字，补录 dict.json 缺失字词（拼音 TONE3 + 释义 + 古义；注释词头收割为双字词）。
4. 若新增主题标签，同步更新 categories.json 与《需求文档》附录 B。
5. 递增 `dataVersion`，跑 `scripts/validate_data.py` 全绿，在《进度日志》记录本次扩充。

大规模流水线（100→200 已实测）：并行 agent 分批生成条目 JSON → Python 合并去重校验 → pypinyin 注音 → 并行补缺字释义与双字词 → 更新 validate_data.py 常量（总数/每类计数/ID 正则 4 位）→ 校验全绿 → 拷贝入 `app/assets/data/` → 构建发版（版本号 +0.0.1）。
