# 古诗文库批量采集与入库 v1.0.0

日期：2026-11-05。负责人已授权构建网站批量采集、转换并导入软件数据库的脚本。本工具已完成小批实测，没有启动长时间全站任务，没有构建APK。

## 主脚本

`scripts/crawl_gushiwenku_v1_0_0.py`

只用项目既有Python及已保存的OpenCC/pypinyin，无新安装、无模型接口、无新增智能体。工具、缓存、下载和报告都在本项目内。

处理链路：公开选集目录 → 按现有待补篇目发现链接 → 限速采集HTML → 原文/作者核对 → 译文、正文词注和来源主题标签转换 → 缺字检查 → 生成译注批次 → 原有备份/同步/校验/回滚入库程序。

默认选集是唐诗三百首、宋词三百首、元曲三百首。它们是公开目录入口，不保证覆盖我们的全部精选名单。古文当前100篇都有译注字段，因此本轮不另扩古文目录或改变名单。

## 使用命令

在hongzhuang-project根目录运行。当前机器Python不在PATH时，PowerShell命令如下：

```powershell
# 预览最多20个作品页面，采集并转换，不正式入库
& 'C:/Users/22946/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe' -B scripts/crawl_gushiwenku_v1_0_0.py --max-pages 20

# 正式导入满足条件的匹配条目
& 'C:/Users/22946/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe' -B scripts/crawl_gushiwenku_v1_0_0.py --max-pages 20 --apply

# 指定一个已知作品；多个--url可连续追加
& 'C:/Users/22946/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe' -B scripts/crawl_gushiwenku_v1_0_0.py --url https://www.gushiwenku.cn/shiwen/064809f/ --max-pages 1 --apply --recheck

# 显式复查之前因缺字、版本、标签等暂缓的页面；只读缓存，不联网
& 'C:/Users/22946/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe' -B scripts/crawl_gushiwenku_v1_0_0.py --offline --recheck --max-pages 20
```

其他电脑有Python命令时可将开头的解释器绝对路径替换为python。网络受沙箱限制的环境需通过环境的联网审批运行；脚本本身没有绕过逻辑。

参数说明：

- `--max-pages`：每次最多处理的作品页面，1～500，默认20。另有robots和显式目录请求，不包含在这个作品上限内。
- `--catalog URL`：可重复，最多10个显式目录；传入后代替默认3个目录。不自动遍历整个网站或无限翻页。
- `--url URL`：可重复指定作品；仅指定作品时不额外读取默认目录。
- `--delay`：新网络请求间隔秒数，最小2秒；缓存命中不等待。
- `--offline`：只读已下载缓存，不请求网络。
- `--recheck`：重新处理此前暂缓或失败的链接。默认跳过这些链接，继续发现其他待补作品，避免同一批缺项无限重复。
- `--apply`：开启正式导入；省略时仅预览与保存候选。
- `--work`：指定项目expansion/下面的工作目录，不能写到项目以外。

## 入库条件与保留项

1. 只更新当前精选范围内的original_only条目；旧作品、ID、原文、收藏/掌握记录及已有译注不改。
2. 目录题名只用于发现，绝不单凭题名认领。导入须原文繁简/去标点归一后匹配且作者匹配；不做不可靠的相似度自动套译文。
3. 题名可与软件的“题名+副题”或“词牌+首句”对应；其他异名留待处理。组诗整组与单首正文不同仍会被拒绝。
4. 译文不能为空、不能为占位；需3～18条正文词注，主题标签须在该类别枚举内。题名专有词注不混作正文词注。
5. 主题来自网页theme-link及现有标签，不随意猜题材。明确映射：山水田园→类别允许的山水/田园，田园→类别允许的田园/山水，送别/离别按类别枚举映射。其他不匹配标签保留缺项。
6. 当前模板是逐段译文，原文/译文段落数不同会暂缓；相同也不证明每句译义正确。
7. 既有字典优先；缺字可复用同页明确的单字正文注释，仅记录上下文古义，不拆解双字词造单字义，不将其当作全面现代义。拼音由现有入库程序生成。其余缺字仍暂缓。
8. 批次标记literaryApproved=false、automaticSourceImport=true；单字源释义同样不声称经过独立审核。网页可访问、robots允许路径、结构完整都不是语义正确或现代译注再分发授权的证明，来源URL和散列保留。

自动结果是“字段齐全且脚本规则通过”，不是“所有内容均已逐篇语义校订”。全量验收不能因这次脚本完成而跳过。

## 断点、安全边界与文件

- 工作目录：expansion/gushiwenku-crawler-v1.0.0/。
- cache/：原始HTML按SHA256存储，URL缓存索引含状态、获取时间、来源URL和散列。已验证样本缓存也会复用；变更或损坏缓存会被拒绝。
- held/：未满足条件的链接和失败记录，不反复自动请求。
- snapshots/：以内容哈希命名的转换记录，包含原始字段、检查结果、候选及来源。
- reports/：每次运行的请求次数、缓存命中、候选数、导入批次及问题；追加保存，不覆盖旧报告。
- 同脚本实例使用独占锁；不要与其他正式入库脚本同时写库。异常退出留下锁时先确认进程已退出，再人工处理锁，不自动删除他人锁。
- 只接受本站HTTPS诗文和选集路径；不扫描随机编号、不采集账号页面、不跟随外站跳转。遇401/403/429/503或验证码停止，不自动重试或换代理；普通缺页和解析缺项留记录。
- 正式入库由apply_enrichment_batch.py生成数据备份，自动更新原所属批次及app/assets/data/，校验/审计失败回滚。此脚本不构建APK。
- 每批自动递增poems/dict数据版本，使用新的enrichment编号；软件APK版本等最终完整验收后统一递增。旧包及检查点不覆盖。
